# Contact Sync

Клиент-серверное приложение для переезда на новый телефон. Android-клиент сохраняет на сервере (Symfony) контакты, пароли и установленные приложения, а на новом телефоне возвращает их обратно. Общие контакты семьи раздаются всем её участникам. Администратор управляет пользователями и семьями через веб-админку.

```
android/   Android-клиент (Kotlin, Jetpack Compose, WorkManager, OkHttp, Autofill Framework)
server/    API и админка (PHP 8.4+, Symfony 7.4, Doctrine ORM, EasyAdmin 5)
docs/      Проектные документы
```

## Возможности

- **Аккаунты.** Вход по email и паролю, регистрация из приложения. Контакты хранятся по пользователю, а не по устройству.
- **Синхронизация.** Вручную и в фоне: раз в 6 часов и через 1–10 минут после изменения телефонной книги.
- **Восстановление.** После входа на новом телефоне личные контакты возвращаются в телефонную книгу. Дубли отсекаются: контакт, который уже есть на телефоне (то же имя и те же номера), не создаётся повторно.
- **Семья.** Администратор объединяет аккаунты в семью и ведёт общие контакты. Они ставятся на телефоны всех участников, даже если у аккаунта нет своих контактов. Изменения и удаления в админке доходят до телефонов при следующей синхронизации (для контактов, которые приложение само положило на телефон).
- **Google-аккаунты.** Приложение передаёт на сервер все Google-аккаунты устройства, они видны в админке.
- **Менеджер паролей.** Хранилище со сквозным шифрованием (мастер-пароль, AES-256-GCM): сервер паролей не видит. Сервис автозаполнения Android подставляет логины в приложения и на сайты, а при входе или смене пароля предлагает сохранить или обновить запись. Прежние пароли остаются в истории, одновременные правки с разных телефонов сводятся без потерь. Разблокировка мастер-паролем или отпечатком. Подробно — [docs/password-manager.md](docs/password-manager.md).
- **Бэкап приложений.** Сервер — точка восстановления: хранит список установленных приложений и APK приложений не из Google Play. Приложение обновляет копию раз в неделю ночью, когда телефон на зарядке и в Wi-Fi (с докачкой); по каждому приложению хранится текущая и прошлая версия (для отката), более старые и APK удалённых приложений сервер удаляет сам. На новом телефоне — экран восстановления: приложения из Play открываются в Play, сохранённые APK ставятся с проверкой подписи. Подробно — [docs/apps-backup.md](docs/apps-backup.md).
- **Админка** (`/admin`). Справочник личных и семейных контактов с поиском и фильтрами, пользователи, семьи, устройства, Google-аккаунты, приложения пользователей (с состоянием бэкапа APK), хранилища паролей (только метаданные и сброс — содержимое зашифровано).

## Модель данных

- `User` — логин (email), пароль, роли, семья (не больше одной).
- `Family` — семейная группа.
- `Contact` — принадлежит **либо** пользователю (личный), **либо** семье (общий). У контакта публичный `uuid` — `serverId` для клиента.
- `Device` — установка приложения у пользователя (`installId` генерируется при установке).
- `ContactTombstone` — след личного контакта, удалённого администратором (чтобы удаление дошло до телефонов).
- `ContactLink` — связь серверного контакта с локальным на конкретном устройстве (`LOOKUP_KEY`). Благодаря ей один контакт на нескольких телефонах не превращается в дубли, а удаление контакта на одном телефоне не трогает контакты, пришедшие с другого.
- `GoogleAccount` — Google-аккаунты с устройств пользователя.
- `ApiToken` — токены API. В БД хранится только SHA-256.
- `Vault`, `VaultItem` — хранилище паролей: параметры ключа и зашифрованные записи с ревизиями.
- `InstalledApp` — приложение на устройстве (версия, источник, подпись, файлы APK). `ApkBlob` — загруженный APK (по SHA-256).

## Как работает синхронизация

Выгрузка (`POST /api/sync`) — полный снимок **личных** контактов устройства:

- контакт, уже связанный с этим устройством, обновляется;
- контакт с `serverId` (восстановлен с сервера или сменил `LOOKUP_KEY`) привязывается к существующему серверному;
- остальные создаются;
- контакты, связанные с устройством, но пропавшие из снимка, удалены на телефоне — на сервере они **только помечаются удалёнными** (`deletedAt`): остаются в базе и в админке, но на телефоны больше не восстанавливаются. Если такой контакт по-прежнему есть на другом телефоне пользователя и приходит оттуда, отметка снимается;
- контакт, **удалённый в админке**, удаляется из базы окончательно, а на сервере остаётся «надгробие» (`ContactTombstone`). Телефон присылает `serverId` известных ему контактов, получает в ответе `removed` и удаляет их из телефонной книги, а не загружает заново;
- контакты с других устройств, которых на этом телефоне ещё нет, не трогаются.

Клиент хранит соответствия «raw-контакт телефона ↔ serverId» в файле приложения. Семейные контакты на телефоне в личную выгрузку не попадают. Если семейный контакт убрали из семьи, приложение удаляет его с телефона — но только если само его создало. Совпавший с уже существовавшим контактом остаётся на телефоне.

Сценарии клиента:

| Когда | Что происходит |
|---|---|
| Вход в аккаунт | восстановить личные → выгрузить телефонную книгу → подтянуть семейные |
| Кнопка и фоновая синхронизация | выгрузить → подтянуть семейные |
| «Восстановить контакты с сервера» | как при входе |

## API

Все запросы, кроме входа и регистрации, — с заголовком `Authorization: Bearer <token>`.

| Метод | Путь | Назначение |
|---|---|---|
| POST | `/api/auth/register` | `{email, password}` → `{token, user}` |
| POST | `/api/auth/login` | `{email, password}` → `{token, user}`. Не больше 5 попыток за 15 минут на пару IP+email |
| POST | `/api/auth/logout` | отозвать текущий токен |
| GET | `/api/me` | `{email, family}` |
| POST | `/api/sync` | выгрузка, см. ниже |
| GET | `/api/contacts` | личные контакты (для восстановления) |
| GET | `/api/family/contacts` | `{family, contacts}` — общие контакты семьи |
| GET, POST, DELETE | `/api/vault` | хранилище паролей: параметры ключа, создание, сброс |
| PUT | `/api/vault/key` | смена мастер-пароля |
| GET, POST | `/api/vault/items` | получение изменений с ревизии `since`; отправка правок с `baseRevision` (конфликт → текущая версия) |
| POST | `/api/apps/inventory` | список приложений устройства → хэши APK, которых нет на сервере |
| GET | `/api/apps` | приложения пользователя для восстановления |
| GET, PUT | `/api/apk/uploads/{sha256}` | состояние загрузки / очередная часть (`?offset=N`) |
| POST | `/api/apk/uploads/{sha256}/complete` | завершить загрузку (проверка SHA-256) |
| GET | `/api/apk/{sha256}` | скачать APK (только свой) |

```json
POST /api/sync
{
  "device": { "installId": "3f2a9c1e-...", "model": "Google Pixel 8" },
  "googleAccounts": ["anna@gmail.com"],
  "contacts": [
    { "externalId": "3789r1-2A", "serverId": null, "name": "Иван", "phones": ["+7 900 111-22-33"], "emails": [] }
  ]
}
→ { "created": 1, "updated": 0, "deleted": 0, "total": 1,
    "links": [{ "externalId": "3789r1-2A", "serverId": "01a0e279-..." }],
    "removed": [] }
```

`removed` — externalId контактов, которые администратор удалил на сервере: клиент удаляет их у себя.

Невалидные данные — `422`, неверный токен — `401`, занятый email при регистрации — `409`.

## Запуск сервера

Нужны Docker (с Compose) и make. Сервер (Symfony на FrankenPHP) и PostgreSQL запускаются в контейнерах.

```bash
make up
```

При первом запуске `make up` сам создаёт `.env` в корне проекта со случайными `APP_SECRET` и паролем базы, собирает образ, поднимает контейнеры, применяет миграции и ждёт готовности сервера. API будет на http://localhost:8001, админка — на http://localhost:8001/admin.

Первый администратор (пароль команда спросит):

```bash
make admin EMAIL=admin@example.com
```

Основные команды (полный список — `make help`):

| Команда | Что делает |
|---|---|
| `make up` / `make down` | запустить / остановить; данные сохраняются в томах Docker |
| `make restart` | перезапустить |
| `make logs` | логи сервера и базы |
| `make admin EMAIL=…` | создать администратора (или сменить пароль) |
| `make user EMAIL=…` | создать пользователя (или сменить пароль) |
| `make apk-cleanup` | удалить APK, которых нет ни на одном устройстве (делается и автоматически) |
| `make test` | тесты сервера в контейнере |
| `make sh`, `make psql` | shell в контейнере сервера, консоль PostgreSQL |
| `make clean CONFIRM=yes` | удалить контейнеры **и все данные** (база, сохранённые APK) |

Настройки — в `.env` в корне проекта: `HTTP_PORT` (по умолчанию 8001), `APK_BACKUP_INCLUDE_PLAY` (сохранять ли APK приложений из Google Play). После правки `.env` выполните `make restart`.

Данные лежат в томах Docker: `database_data` — PostgreSQL, `apk_storage` — сохранённые APK. Миграции применяются автоматически при каждом старте контейнера.

Для продакшена сервер нужно поставить за обратный прокси с HTTPS: release-сборка клиента ходит только по HTTPS.

### Без Docker

Для разработки сервер можно запустить и локально: PHP 8.4+ с `pdo_sqlite` и Composer.

```bash
cd server
composer install
php bin/console doctrine:migrations:migrate -n
php bin/console app:user:create admin@example.com --admin
php -S 0.0.0.0:8001 -t public
```

Так используется SQLite (`var/data_dev.db`). Тесты: `php bin/phpunit`. Миграции переносимые: они и тесты проверены на SQLite и PostgreSQL 16.

## Запуск клиента

Клиент собирается локально (нужен Android SDK), не в Docker. Откройте `android/` в Android Studio или соберите из консоли:

```bash
make install-apk
```

Команда соберёт debug APK, поставит его на подключённое по USB устройство и пробросит на него порт сервера (`adb reverse`). Адрес сервера по умолчанию для сборки задаётся так: `make install-apk SERVER_URL=http://94.103.9.172:8001` (в приложении его можно поменять на экране входа). В приложении укажите адрес `http://127.0.0.1:8001`. Проброс сбрасывается при переподключении устройства — тогда выполните `make reverse`.

Unit-тесты (сопоставление контактов, шифрование, правила обновления паролей, синхронизация хранилища двух телефонов с фейковым сервером): `./gradlew testDebugUnitTest`.

Минимальная версия Android — 8.0 (API 26): ниже нет Autofill Framework.

Адрес сервера вводится на экране входа. По умолчанию — `http://10.0.2.2:<HTTP_PORT>` (хост-машина из эмулятора, порт берётся из `.env` при сборке). Для телефона — `http://127.0.0.1:8001` через `make reverse` или IP компьютера в локальной сети. HTTP без TLS разрешён только в debug-сборке, release ходит только по HTTPS.

Разрешения: `READ_CONTACTS`, `WRITE_CONTACTS`, `GET_ACCOUNTS` (запрашиваются сразу после входа); `QUERY_ALL_PACKAGES` и `REQUEST_INSTALL_PACKAGES` — для бэкапа и восстановления приложений; `USE_BIOMETRIC` — разблокировка паролей по отпечатку. Автозаполнение включается в системных настройках (кнопка на экране «Пароли»).

## Ограничения

- **Google-аккаунты.** С Android 8 приложение видит через `AccountManager` только «свои» аккаунты. Поэтому аккаунты берутся ещё и из телефонной книги — это те Google-аккаунты, у которых включена синхронизация контактов. Аккаунт без синхронизации контактов на Android 8+ не будет найден.
- **Куда пишутся контакты.** Восстановленные и семейные контакты записываются в память телефона (без привязки к аккаунту), а не в Google-аккаунт.
- **Правки личных контактов в админке** на телефон сами не приходят: личные контакты возвращаются на телефон только при восстановлении. Удаление в админке приходит при следующей синхронизации. Семейные контакты приходят при каждой синхронизации — и правки, и удаления.
- **Токен** хранится в приватных SharedPreferences приложения, без дополнительного шифрования. Данные приложения исключены из облачного бэкапа и переноса на новый телефон — там нужно войти заново.
- **Сессии сторонних приложений** не переносятся — это запрещено песочницей Android. Переносятся логины и пароли (через менеджер паролей) и сами приложения.
