# CEP — цепочки VPN для macOS

Приложение собирает цепочку из нескольких VPN-узлов: Mac → узел 1 → узел 2 → … → интернет.
Сервер каждого следующего узла доступен только через туннель предыдущего, весь остальной трафик уходит в последний узел.

Протоколы: Argon4, VLESS, Hysteria 2, Hysteria (v1), AmneziaWG, OpenVPN, OpenConnect (AnyConnect/ocserv, GlobalProtect, Pulse, Fortinet и др.), SSTP. Argon4 также работает как шифрующая надстройка над любым другим профилем.

## Сборка и запуск

```bash
./scripts/install-deps.sh      # brew-пакеты + сборка amneziawg-go/awg
./scripts/build-app.sh         # Swift + Go Argon4-помощник → build/CEP.app
open build/CEP.app
```

Нужны macOS 14+, Swift 5.10+ и Go 1.25+ (`install-deps.sh` устанавливает Go, если его нет). Тесты: `swift test` и `cd argon4 && go test -race ./...`.

## Установка на другой Mac

```bash
./scripts/make-dmg.sh          # → build/CEP.dmg
```

`build-app.sh` кладёт внутрь `CEP.app` все VPN-программы (`Contents/Helpers`), их библиотеки (`Contents/Frameworks`) и корневые сертификаты macOS (`Resources/cacert.pem`). Homebrew на другом Mac не нужен. Собирать по-прежнему нужно на Mac, где установлены зависимости (`install-deps.sh`).

1. **Копирование.** Перенесите `CEP.dmg` на другой Mac, откройте его и перетащите `CEP` в «Программы».
2. **Первый запуск.** Сборка подписана ad-hoc, без Developer ID, поэтому macOS не даст открыть скачанное приложение. Снимите карантин:
   ```bash
   xattr -dr com.apple.quarantine /Applications/CEP.app
   ```
   Другой способ — «Системные настройки → Конфиденциальность и безопасность → Всё равно открыть».
3. **Профили.** На старом Mac: «+» → «Экспорт профилей и цепочек…». На новом: «Импорт профилей и цепочек…». В файле пароли и ключи — передавайте его как секрет и удалите после импорта.

Ограничения сборки:
- **Только Apple Silicon (arm64).** Для Intel Mac нужно собирать на Intel или из универсальных бинарников.
- **macOS не старше той, на которой собирали brew-пакеты.** Бинарники Homebrew собираются под текущую версию системы.
- **Без предупреждения Gatekeeper** приложение откроется только с подписью Developer ID и нотаризацией (`codesign --options runtime` + `notarytool`). Для этого нужен платный аккаунт Apple Developer.

## Как пользоваться

1. «+» → «Профиль из ссылки…» — вставить одну или несколько ссылок `vless://`, `hy2://`, `hysteria2://`, `hysteria://`.
   Остальные протоколы: «+» → «Новый профиль». Для OpenVPN и AmneziaWG вставляется или загружается из файла `.ovpn`/`.conf`.
2. «+» → «Новая цепочка», затем «Добавить узел» в нужном порядке.
3. «Подключить» — macOS спросит пароль администратора: движку нужен root для туннелей и маршрутов.
4. В разделе «Подключение» видно состояние каждого узла и журналы. «Отключить» — там же или в строке меню.

Настройка Argon4:
- **Отдельный узел.** Создайте профиль `Argon4`, укажите `host[:port]` (по умолчанию UDP `51820`), мастер-пароль и при необходимости `Client ID`/`Client Secret`. Пустой `Client ID` заменяется на UUID профиля.
- **Надстройка.** В профиле другого протокола включите «Шифровать подключение через Argon4» и заполните параметры Argon4. Движок сначала поднимет Argon4, а затем направит через него подключение к серверу основного профиля.
- Профили `argon4` совместимы по полям с Android-версией CEP. Пароли сохраняются в `profiles.json` с правами `0600`.

## Устройство

| Часть | Что делает |
|---|---|
| `Sources/CEP` | SwiftUI-приложение: профили, цепочки, статус, значок в строке меню |
| `Sources/cep-engine` | Движок под root: поднимает узлы, прокладывает маршруты, следит за процессами, снимает всё при остановке |
| `Sources/CEPCore` | Модели, разбор ссылок и конфигов, генерация конфигов xray/sing-box, работа с сетью и DNS |
| `argon4` | Go-помощник `cep-argon4`: Argon2id, X25519-handshake, AES-256-GCM, anti-replay и двунаправленный TUN |

Приложение и движок обмениваются файлами в `~/Library/Application Support/CEP/run/`:
- `plan.json` — задание с паролями, движок удаляет его сразу после чтения;
- `status.json` — состояние, которое опрашивает приложение;
- `stop` — команда остановки;
- `engine.log` и `hopN.log` — журналы.

Конфиги узлов с паролями и скрипт OpenConnect движок держит в `/var/run/cep` (root, 0700) и удаляет при остановке.

Как движок поднимает цепочку:
1. Запоминает исходный шлюз и заранее разрешает адреса всех серверов системным DNS. Берутся все IPv4-адреса имени, чтобы клиент не ушёл мимо цепочки на другой адрес из round-robin.
2. Для узла N добавляет host-маршруты до его сервера: для первого узла — через исходный шлюз, для остальных — через интерфейс узла N-1. Затем запускает клиент и ждёт появления его интерфейса.
3. Клиентам запрещено менять маршруты:
   - OpenVPN запускается с `--route-noexec` и `--script-security 1`;
   - OpenConnect работает со своим скриптом вместо vpnc-script;
   - pppd у SSTP запускается с `nodefaultroute`;
   - TUN у sing-box работает без `auto_route`.
4. После последнего узла добавляет `0.0.0.0/1` и `128.0.0.0/1` в его интерфейс, IPv6 `2000::/3` отправляет в blackhole и подменяет DNS основного сервиса (ключ `State:` в configd).
5. Если какой-то клиент упал, вся цепочка снимается, маршруты и DNS возвращаются.

Внутренние сети узла:
- **Сети от сервера.** Split-include OpenConnect и `route` из PUSH_REPLY OpenVPN движок прокладывает через интерфейс этого узла, где бы он ни стоял в цепочке. Маршрут по умолчанию от сервера не берётся.
- **Внутренний DNS.** Если сервер прислал DNS и домен, имена этого домена резолвятся через DNS за узлом (split DNS, `SupplementalMatchDomains`), остальные — через DNS цепочки.
- **Поле профиля «Сети через этот узел».** Например, `192.168.1.119, 10.0.0.0/8`. Адрес из своей локальной подсети задаётся отдельно (`/32`): маршрут на всю подсеть уже занят локальной сетью, добавить его не получится.
- **Где видно.** Применённые сети показываются под узлом в разделе «Подключение» и в `engine.log`. Проверить конкретный адрес: `route -n get 192.168.1.119` — интерфейс должен быть интерфейсом узла.

Как поднимаются отдельные протоколы:
- **Argon4:** встроенный `cep-argon4` выполняет handshake с тремя попытками, получает IPv4/MTU от сервера и обменивается сырыми IP-пакетами через собственный `utun`. Конфиг с секретами передаётся файлом `0600` в `/var/run/cep` и удаляется сразу после чтения. Сети из handshake добавляются через интерфейс узла.
- **Прокси (VLESS, Hysteria):** узлом цепочки становится TUN sing-box с адресом `172.19.<N>.1/30`. VLESS обслуживает xray: он поддерживает Reality, Vision, xhttp, ws, grpc и httpupgrade и отдаёт SOCKS на `127.0.0.1:2080N`, а sing-box заворачивает этот SOCKS в TUN. Hysteria 2 и Hysteria v1 sing-box обслуживает напрямую.
- **AmneziaWG:** `amneziawg-go` и `awg setconf`. Ключи wg-quick (`Address`, `DNS`, `MTU` и т.п.) движок применяет сам. Узел считается поднятым после первого рукопожатия.
- **SSTP:** `sstpc` с параметрами pppd.

## Ограничения

- `sstpc` и `openconnect` подключаются по имени хоста. Движок ставит маршруты на все IPv4-адреса имени, а OpenConnect дополнительно получает `--resolve`.
- В `.ovpn` не поддерживаются блоки `<connection>`. Из нескольких `remote` берётся первый.
- Ссылки Hysteria 2 с перескоком портов (`host:443,20000-30000`) не поддерживаются.
- Только IPv4 внутри цепочки. IPv6 по умолчанию блокируется.
- Автоматического переподключения Argon4 после смены сети пока нет: разорвите цепочку и подключите её заново.
- DNS подменяется в динамическом слое configd. Если DNS задан вручную в «Системных настройках», действует он, но запросы всё равно уходят через цепочку. Исключение — DNS-сервер в локальной сети.
- Если узлы вложены друг в друга, каждый следующий туннель добавляет накладные расходы к MTU. При проблемах с большими пакетами уменьшите MTU у внутренних узлов.
- Профили с паролями лежат в `~/Library/Application Support/CEP/profiles.json` (права 0600), не в связке ключей.
- Движок запускается через `do shell script … with administrator privileges`, без привилегированного помощника (SMAppService): для него нужна подпись Developer ID. Движок сам ищет программы в `/opt/homebrew/bin`, `/usr/local/bin` и т.п. Эти каталоги доступны пользователю на запись, поэтому подмена бинарника там равносильна запуску своего кода под root.

## Терминальный клиент для Ubuntu

`cep-cli` поднимает цепочку из совместимого с macOS `profiles.json`: каждый следующий сервер доступен через TUN предыдущего узла, после последнего добавляются маршруты `0.0.0.0/1` и `128.0.0.0/1`.

Поддерживаются Argon4 (включая `useArgon`-надстройку), VLESS, Hysteria 2, Hysteria v1, OpenConnect и OpenVPN. AmneziaWG в Linux CLI пока не поддерживается. SSTP пока отклоняется не из-за ограничения протокола, а потому что обвязка `sstpc` + `pppd` и управление её маршрутами перенесены только в macOS-движок, но ещё не в Linux CLI.

### Сборка

Сборка выполняется из исходников через корневой `Makefile` на целевой Ubuntu, поэтому архитектура машины определяется автоматически:

```bash
make cep-linux
# бинарники: cep/build/linux-<архитектура>/
```

Эта цель также проверяет Go, `iproute2`, `resolvectl`, `openconnect`, `openvpn`, `xray` и `sing-box`. Отсутствующие apt-пакеты устанавливаются через `sudo`; `xray` и `sing-box` скачиваются из официальных релизов в `/usr/local/bin`. Уже установленные программы не обновляются и не скачиваются повторно. Версия Go toolchain, требуемая `go.mod`, загружается средствами Go и кэшируется.

Go-модули скачиваются заново только после изменения `go.mod`/`go.sum`; бинарники пересобираются только после изменения исходников. Поэтому повторный `make cep-linux` без изменений не запускает ни установку, ни компиляцию.

Для явной кросс-сборки можно задать платформу, например `make cep-linux GOOS=linux GOARCH=arm64`. Тесты запускаются через `make test-cep-linux`. Управление зависимостями:

```bash
make cep-linux CEP_INSTALL_DEPS=0                 # только проверка/сборка без установки
make cep-linux-deps                              # только недостающие зависимости
CEP_UPDATE_TOOLS=1 make cep-linux-deps           # принудительно поставить закреплённые Xray/sing-box
make cep-linux SING_BOX_VERSION=1.14.3 XRAY_VERSION=26.3.27
```

### Установка как systemd-сервис

На Ubuntu из корня репозитория:

```bash
make install-cep-linux
```

Команда собирает бинарники под текущую архитектуру, устанавливает их в `/opt/cep`, затем запускает последовательный мастер:

1. задайте название цепочки;
2. добавьте узлы в порядке подключения: Argon4 первым, затем остальные при необходимости;
3. выберите цепочку, которую должен запускать сервис;
4. дождитесь проверки синтаксиса и доступности, создания unit-файла и запуска.

Профили сохраняются в `/etc/cep/profiles.json` с правами `0600`, UUID активной цепочки — в `/etc/cep/chain-id`. Установщик создаёт `/etc/systemd/system/cep-chain.service`, включает автозапуск и через несколько секунд проверяет `systemctl is-active`; при падении показывает status и последние записи journald.

Добавление узлов и изменение цепочек после установки:

```bash
make configure-cep-linux
make cep-service-status
make cep-service-logs       # Ctrl-C завершает только просмотр журнала
make cep-service-restart
make cep-service-stop
make cep-service-start
```

Если нужно только установить собранные программы без настройки и запуска, используйте `make install-cep-linux CEP_CONFIGURE=0`, затем `make configure-cep-linux`.

### Мастер и проверки без установки сервиса

```bash
CEP_BIN="cep/build/linux-$(go env GOARCH)"
"$CEP_BIN/cep-cli" wizard -profiles /secure/path/profiles.json
"$CEP_BIN/cep-cli" add-node -profiles /secure/path/profiles.json
"$CEP_BIN/cep-cli" list -profiles /secure/path/profiles.json
"$CEP_BIN/cep-cli" check -profiles /secure/path/profiles.json -chain "Моя цепочка"
```

Мастер умеет создавать все поддерживаемые Linux-профили, читает `.ovpn` из файла, сохраняет формат macOS и атомарно заменяет `profiles.json` только после завершения настройки. `add-node` отдельно добавляет узлы в выбранную существующую цепочку.

`check` сначала выполняет обязательную проверку синтаксиса. Затем проверяет TCP-подключение к TCP-узлам и настоящий Argon4-handshake. Ошибка сети на этом этапе — только предупреждение: следующий узел может быть намеренно недоступен напрямую и открыться через предыдущий туннель. Для UDP Hysteria/OpenVPN простой `DialUDP` доступность не доказывает, поэтому окончательная проверка происходит handshake при запуске.

### Запуск в foreground

Файл содержит пароли и ключи, поэтому сначала ограничьте доступ:

```bash
chmod 600 /secure/path/profiles.json
CEP_BIN="cep/build/linux-$(go env GOARCH)"

"$CEP_BIN/cep-cli" validate -profiles /secure/path/profiles.json -chain "Моя цепочка"
sudo "$CEP_BIN/cep-cli" up -profiles /secure/path/profiles.json -chain "Моя цепочка"
```

Если цепочка одна, `-chain` можно не передавать. Журналы узлов: `/run/cep-linux/hopN.log`; каталог меняется флагом `-run-dir`. Для DNS используется `systemd-resolved` (`resolvectl`), символическая ссылка `/etc/resolv.conf` не перезаписывается. Если автоматическая настройка DNS не нужна, задайте в цепочке пустой список `dns` и настройте DNS самостоятельно. `Ctrl-C` останавливает процессы и удаляет добавленные маршруты и DNS.

Оставьте `cep-cli` и `cep-argon4` в одном каталоге. Пути к программам можно переопределить переменными `CEP_ARGON4`, `CEP_OPENCONNECT`, `CEP_OPENVPN`, `CEP_XRAY`, `CEP_SING_BOX`; каталог установки внешних инструментов — `CEP_INSTALL_PREFIX`.

Ограничения Linux CLI: только IPv4 внутри цепочки, нет автоматического переподключения после смены сети, split DNS по доменам не настраивается. Остановка по `SIGTERM`, `SIGHUP` или `Ctrl-C` выполняет ту же очистку, что и штатное завершение.

## Android

Версия для Android лежит в `android/`. Профили и цепочки те же: файл `profiles.json` с Mac переносится как есть
(«Профили» → «Добавить» → «Загрузить profiles.json с Mac…»), обратно — «Сохранить profiles.json…».

```bash
cd android
./build-engine.sh                   # движок → app/libs/cepcore.aar (Go, gomobile, NDK)
./gradlew installDebug              # сборка и установка на подключённый телефон
```

Тесты движка: `cd android/engine && go test -tags with_gvisor,with_quic,with_utls,with_openconnect,with_openvpn ./...`.

Устройство:
- **Без root.** Вся цепочка — один экземпляр sing-box 1.14 внутри `VpnService` (`android/engine`, пакет `cepcore`).
  Узел N выходит в сеть через узел N-1 (`detour`), трафик TUN уходит в последний узел (`route.final`),
  «Сети через этот узел» — правило `ip_cidr` на свой узел. Сокеты движка выводятся из VPN через `VpnService.protect`.
- **Протоколы.** VLESS, Hysteria 2 и Hysteria v1 — outbound'ы sing-box (VLESS тоже через sing-box, xray не встроен);
  OpenConnect и OpenVPN — userspace-endpoint'ы sing-box 1.14, без системных интерфейсов.
- **Адреса серверов** движок разрешает системным DNS до подъёма VPN и подключается по IP; SNI и проверка сертификата — по имени.
- **DNS** цепочки ставится в VPN как DNS устройства, запросы идут через цепочку. IPv6 при «Блокировать IPv6» Android блокирует сам:
  у VPN нет адресов и маршрутов IPv6.

Ограничения Android-версии:
- AmneziaWG и SSTP не поддерживаются: в sing-box их нет. Профили сохраняются и переносятся, но цепочку с ними не запустить.
- VLESS с транспортом `xhttp` и `tcp` с `headerType=http` не поддерживаются (это умеет только xray).
- OpenConnect: Array Networks не поддерживается. Отпечаток сертификата передаётся в sing-box как есть.
- OpenVPN: сертификаты и ключи — только внутри `.ovpn` блоками `<ca>`, `<cert>`, `<key>`, `<tls-auth>`, `<tls-crypt>`; режим static key не поддерживается.
- Split DNS по доменам от сервера (как `SupplementalMatchDomains` на macOS) нет: все запросы идут на DNS цепочки.
