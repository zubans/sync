# Резервное копирование приложений и их авторизаций

Статус: список приложений, бэкап APK и восстановление — реализованы. Перенос логинов — через [менеджер паролей](password-manager.md). Перенос сессий сторонних приложений невозможен (см. ниже).

## Что можно, а что нет

| Что | Можно ли | Как сделано |
|---|---|---|
| Список приложений | Да | `PackageManager` + `QUERY_ALL_PACKAGES` |
| Сами APK (base + split) | Да | Файлы из `ApplicationInfo.sourceDir` и `splitSourceDirs` читаются без root |
| Установка на новом телефоне | Да, каждую подтверждает пользователь | `PackageInstaller`; без подтверждений — только в режиме Device Owner |
| Логины и пароли | Да | Менеджер паролей со сквозным шифрованием и автозаполнением |
| Сессии и данные сторонних приложений | **Нет** | Песочница Android: данные приложения читает только оно само и система |

## 1. Список приложений

Клиент собирает пользовательские приложения — без системных: встроенных в прошивку и служебных компонентов без иконки в лаунчере (Android System SafetyCore, Key Verifier и т.п., которые Google ставит через Play). По каждому — пакет, название, версия, источник установки (`getInstallSourceInfo`), SHA-256 сертификата подписи, файлы base и split APK с размером и SHA-256. Хэши кэшируются по «путь + размер + время изменения», поэтому APK на сотни мегабайт не пересчитываются каждый раз.

`POST /api/apps/inventory` сохраняет список (`InstalledApp`, по устройствам). Пропавшие с устройства приложения помечаются удалёнными. В ответе — хэши APK, которых на сервере ещё нет.

## 2. Хранение APK

- **Что сохраняем.** APK всех пользовательских приложений, независимо от источника установки (Google Play, RuStore, браузер, adb). Предел — `APK_MAX_SIZE` на приложение (по умолчанию 1 ГБ).
- **Дедупликация.** Файлы хранятся по содержимому (`var/storage/apk/ab/cd/<sha256>.apk`). Одинаковый APK у разных пользователей лежит один раз. Скачать файл может только тот, у кого он был установлен.
- **Загрузка частями с докачкой.** Куски по 4 МБ. `GET /api/apk/uploads/{sha}` возвращает, с какого байта продолжать. `PUT …?offset=N` дописывает кусок: неверное смещение — `409` с правильным. `POST …/complete` проверяет SHA-256: не совпал — загрузка сбрасывается. Обрыв связи или остановка воркера не теряют сделанного.
- **Когда.** Раз в неделю ночью, только на зарядке и по Wi-Fi. WorkManager не умеет планировать на время суток, поэтому каждую ночь около 02:00 ставится проверка с условиями «зарядка + Wi-Fi». Она запускает бэкап, только если сейчас ночь (до 06:00) и с последнего успешного бэкапа прошла неделя (с запасом в полдня, чтобы время не «уползало»). Не было зарядки этой ночью — бэкап пройдёт следующей. Кнопка «Сохранить сейчас» запускает бэкап сразу (только Wi-Fi, без зарядки) и тоже считается недельным. Если не всё успели за один запуск (WorkManager даёт около 10 минут), бэкап продолжится с места обрыва.
- **Текущая и прошлая версии.** По каждому приложению сервер хранит APK текущей версии и прошлой — для отката. Когда устройство сообщает новую версию, текущая становится прошлой, но только если её APK действительно сохранён: не успела загрузиться новая версия — прошлой остаётся последняя сохранённая. Всё, что старше прошлой версии, и APK приложений, удалённых со всех устройств, сервер удаляет после каждой сверки. Брошенные недокачанные загрузки удаляются через сутки. Вручную — `make apk-cleanup`.
- **Обновления приложений** сервер не делает и не предлагает: приложения обновляются своими штатными механизмами (RuStore, Google Play). Сервер только хранит то, что установлено, для восстановления.
- **Защита сервера.** Загружать можно только файлы из своей инвентаризации, подлежащие бэкапу по политике, и не больше заявленного размера. Сервер — не файлообменник.
- **Хранилище.** Сейчас диск сервера (`APK_STORAGE_DIR`). Для продакшена — отдельный том или S3-совместимое хранилище: интерфейс `ApkStorage` это позволяет.

## 3. Восстановление

Экран «Приложения» показывает приложения со всех устройств пользователя (по каждому пакету — самую свежую версию, удалённые не показываются):

- уже установлено той же или более новой версии → «Установлено»;
- иначе — выбор, откуда восстанавливать (показываются доступные варианты):
  - «Из архива» (APK сохранён): скачать все части, проверить SHA-256 каждой и подпись, поставить одной сессией `PackageInstaller`. Система покажет подтверждение;
  - кнопка магазина, из которого приложение ставили (Google Play, RuStore, AppGallery, Galaxy Store, GetApps, Amazon Appstore, F-Droid — по `installer`), открывает карточку приложения в этом магазине; магазина на телефоне нет — его сайт, если есть;
- APK не сохранён и приложение не из известного магазина (браузер, adb) → «Нет копии APK».

Откат на прошлую версию: у приложения в списке есть кнопка «Прошлая версия». Android не устанавливает старую версию поверх новой (защита от отката), поэтому, если приложение установлено, оно сначала удаляется через системный диалог — **данные приложения на телефоне при этом удаляются**. На телефон, где приложения нет, прошлая версия ставится сразу.

Проверки перед установкой:

- пакет в APK тот же, что ожидаем;
- сертификат подписи совпадает с сохранённым при бэкапе;
- если приложение уже стоит с другой подписью — не ставим: Android всё равно откажет, а это признак подмены.

Нужно разрешение «Установка неизвестных приложений» для Contact Sync — приложение предложит открыть настройку.

## 4. Авторизация в сторонних приложениях

Токены, cookies и базы приложений лежат в `/data/data/<пакет>`. Доступ туда есть только у самого приложения и у системы. Это принципиальная защита Android, а не ограничение, которое можно обойти.

Что сделано и что возможно:

1. **Менеджер паролей** (сделано, [password-manager.md](password-manager.md)): логины и пароли сохраняются при входе и подставляются автозаполнением на новом телефоне. Повторный вход нужен, но без ввода паролей.
2. **Системный перенос Android** (Google One Backup, перенос при настройке нового телефона) переносит данные приложений, которые это разрешили, включая часть сессий. От нас не зависит, но с ним сочетается.
3. **Block Store / Credential Manager самих приложений** — приложения, которые их используют, восстанавливают сессию сами.
4. **Device Owner / MDM** даёт тихую установку, но не доступ к данным чужих приложений.
5. **Root / `adb backup`** — не подходит для массового продукта: `adb backup` с Android 12 почти ничего не сохраняет, root ломает Play Integrity (перестают работать банки).

## Распространение

`QUERY_ALL_PACKAGES` и `REQUEST_INSTALL_PACKAGES` в Google Play требуют обоснования при публикации (бэкап приложений — допустимый сценарий, но с проверкой). Вне Play (корпоративно, через MDM) ограничений нет.
