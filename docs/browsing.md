# История браузеров

Приложение собирает адреса, которые пользователь открывает в браузере, и раз в час выгружает их на сервер. В админке история видна по пользователям и устройствам.

## Как собирается

Прямого доступа к истории браузеров у стороннего приложения нет: Chrome, Яндекс, Firefox и другие держат её в своих закрытых базах. Поэтому адрес читается из **адресной строки** через службу специальных возможностей (`NavBarService`) — ту же, что рисует панель навигации и лампочку VPN. Когда в браузере завершён переход, служба берёт текст поля адреса и кладёт его в очередь.

Из этого следуют ограничения:

- **Пишутся только переходы, совершённые при включённой службе.** Старую историю получить нельзя.
- **Адрес — такой, каким его показывает браузер.** Chrome в спокойном состоянии показывает только домен (без схемы и пути), поэтому чаще всего сохраняется домен, а не полный URL.
- Поле в фокусе (пользователь набирает запрос) пропускается — пишутся только совершённые переходы, а не то, что набирают.
- Режим инкогнито не отдаёт адрес в дерево доступности — такие страницы не попадают.
- Для каждого браузера нужен свой идентификатор поля адреса (`BrowserHistory.URL_BARS`). При смене вёрстки браузера его придётся обновить.

Поддерживаются Chrome (stable/beta/dev и Chromium), Яндекс.Браузер, Mi Browser, Samsung Internet и Firefox.

### На устройствах Xiaomi (Poco, HyperOS)

- Службу специальных возможностей для приложения, установленного из APK, сначала нужно разблокировать: «О приложении» → ⋮ → «Разрешить ограниченные настройки».
- Чтобы почасовая выгрузка и служба не останавливались, включите «Автозапуск» и «Нет ограничений» в разделе экономии батареи.

## Как выгружается

Очередь посещений лежит в файле приложения (`BrowsingStore`, `browsing.json`), привязана к вошедшему пользователю и очищается при выходе. Повтор того же адреса подряд не пишется, размер очереди ограничен (хранятся самые свежие).

`BrowsingSyncWorker` — периодическая задача WorkManager раз в час (при сети). Она отправляет очередь на `POST /api/browsing` и удаляет из неё отправленное; что добавилось во время выгрузки, остаётся на следующий раз. Задача ставится и снимается вместе с остальной фоновой синхронизацией (`SyncScheduler.enable/disable`).

## Сервер

- `POST /api/browsing` (`BrowsingController`) — `{device, visits: [{url, title?, browser?, visitedAt}]}`, `visitedAt` в миллисекундах. Устройство находится или создаётся по `installId`, как при синхронизации контактов. Дубли при повторной выгрузке отсекаются по SHA-256 от адреса и времени в паре с устройством (`BrowsingVisit.dedupHash`, уникальный индекс `device_id + dedup_hash`). Ответ — `{saved}`.
- `BrowsingVisit` — посещение: владелец (`user`, CASCADE), устройство (`device`, SET NULL), адрес, заголовок, пакет браузера, время посещения и время записи.
- В админке — раздел «История браузеров» (`BrowsingVisitCrudController`, только просмотр): фильтры по пользователю, устройству, браузеру и дате, поиск по адресу и заголовку.
