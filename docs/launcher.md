# Главный экран планшета

`LauncherActivity` (пакет `launcher`) — домашний экран (`category.HOME`) для планшета на подставке. У него своя задача (`taskAffinity` `com.example.contactsync.home`), у «Базы знаний» — тоже (`…kb`). Без этого иконки самого приложения из шторки (с флагом `NEW_TASK`) открывали задачу с тем же сродством — главный экран — и «не открывались». Он тёмный, рассчитан на портретную и альбомную ориентацию. На узком экране (меньше 700 dp) карточки идут одна под другой.

Экранов три: первый — дашборд, второй — веб-интерфейс базы знаний (KB), третий — VS Code (code-server). Экраны листают свайпом, на любой экран переходят нажатием на точку под экранами. На втором и третьем экране обычный горизонтальный жест отдан веб-странице: экран листает только резкий горизонтальный взмах одним пальцем (от 100 dp за 0,4 с, по горизонтали вдвое больше, чем по вертикали) в любом месте экрана — его лаунчер перехватывает раньше WebView. Медленные, косые и многопальцевые жесты достаются странице. На главный экран возвращают ещё кнопка «← Главная», «Назад» и «Домой». Док с кнопками навигации общий для всех экранов. Все три экрана держатся созданными, чтобы веб-страницы не перезагружались при каждом возврате на дашборд.

## Что на экране

| Блок | Источник | Обновление |
|---|---|---|
| Часы и дата | системное время | каждую минуту |
| Погода: сейчас, 5 точек через 3 часа, 4 дня (подробно — сутки по часам и 8 дней) | MET Norway `locationforecast/2.0/compact` | раз в 30 минут |
| Мосбиржа | MOEX ISS, данные с задержкой 15 минут | раз в минуту |
| Ближайшее: события на 14 дней | `CalendarContract.Instances` всех видимых календарей | раз в минуту и при возврате на экран |
| Новости: РГ, РБК, CNN, New York Post, New York Times | сервер sync (`/api/news`), он собирает ленты изданий | раз в 5 минут |
| Поиск Яндекса | подсказки `suggest.yandex.ru/suggest-ff.cgi`, поиск — `yandex.ru/search` в браузере | при вводе |
| Лампочка VPN | интерфейс `oc0` и ответ KB через туннель | раз в 10 секунд |
| База знаний: проект, задачи со стадиями, запись встречи | KB, cookie-сессия пользователя | 15 с, пока модель работает, иначе 60 с |
| Док и все приложения | `PackageManager`, активности `category.LAUNCHER` | при возврате на экран |

Данные обновляются, только пока экран открыт (`onResume`/`onPause`). Если сети нет, на экране остаются последние данные и появляется пометка «нет связи».

## Управление

- **Город** — нажать на погоду. Поиск идёт через геокодер Open-Meteo.
- **Инструменты** — «Добавить» в карточке Мосбиржи. Искать можно по тикеру, ISIN или названию. Убрать — долгим нажатием. При добавлении определяется основной режим торгов бумаги (`/iss/securities/{secid}.json`, `is_primary`). Котировки запрашиваются одним запросом на каждый режим торгов.
- **Док** — долгое нажатие на приложение в шторке. Шторка открывается кнопкой «⋯» или свайпом вверх. Док хранит не пакет, а конкретную иконку (компонент `пакет/.Активность`): у sync три иконки — «Синхронизация», «База знаний», «Файлы», и по пакету док показывал случайную из них. Старые записи-пакеты при загрузке заменяются главной иконкой пакета.
- **События** — нажатие открывает событие в календаре (просмотр и правка), «+ Событие» — форма нового события. Системный «Календарь» прошивки урезан: в нём нет экрана редактирования (`EditEventActivity`), и он падает. Поэтому стоит Etar (`ws.xsoh.etar`, F-Droid, GPL-3.0) — свободный форк того же календаря, и главный экран открывает события в нём, если он установлен.
- **Новости** — вкладка издания или «Все»; нажатие на заголовок открывает статью в браузере.

Настройки хранятся локально (`SharedPreferences` `launcher`). На сервер они пока не передаются.

## Решения

- **Котировки.** Для разных рынков ISS отдаёт разные колонки. Цена берётся из `LAST`, а если её нет — из `CURRENTVALUE` (индексы) или `LASTVALUE`. До первой сделки дня показывается `PREVPRICE` без изменения. Цена облигаций — в процентах от номинала, рядом доходность `YIELD`.
- **Погода.** Прогноз Open-Meteo из нашей сети недоступен (соединение обрывается по таймауту), поэтому прогноз берётся у MET Norway. Ему нужен `User-Agent` с названием приложения и не больше 4 знаков в координатах. «Ощущается как» MET Norway не отдаёт, поэтому показывается ветер. Дни собираются из почасовых точек: минимум и максимум за местные сутки, погода берётся по точке, ближайшей к полудню.
- **События на весь день.** `CalendarContract` хранит их от полуночи UTC, поэтому их дата считается в UTC, а не в поясе устройства.
- **Время.** Часы, погода и события используют часовой пояс устройства. Пояс должен быть настроен правильно.

## База знаний

Пакет `kb`: виджет на первом экране, второй экран и отдельная иконка «База знаний» (`KbActivity`).

- **Вход** — логином и паролем KB (`POST /api/login`). KB выдаёт cookie-сессию на 30 дней, она хранится в приватных настройках приложения; пароль не хранится. Токены API не подходят: ими нельзя создать встречу и прикрепить аудио. Если войти прямо на веб-странице второго экрана, приложение забирает её cookie (`/api/me`), и виджет тоже начинает работать. Адрес KB по умолчанию — `http://192.168.100.247:8580`; он доступен только через туннель openconnect (см. «Лампочка VPN»). Для этого адреса в `network_security_config` разрешён HTTP.
- **Задачи** — открытые задачи выбранного проекта (`/api/projects/{slug}/tasks?status=open`). Стадия берётся из последнего прогона модели (`task.run.status`, авторевью — `run.reviewStatus`), а без прогона — из статуса задачи (`KbStages`). Сверху то, что модель делает сейчас, потом ждущее ревью. Нажатие открывает задачу в браузере (`/projects/{slug}/tasks/{id}`, эпики — `/epics/{id}`). Событий KB не присылает, поэтому приложение опрашивает её, только пока экран виден.
- **Запись** — кнопка «Записать» в виджете, на втором экране и в «Базе знаний»; проект заранее не выбирается. Что писать, решает режим звука в момент старта (`CallWatcher.currentSource`):
  - обычный режим — **встреча**, только микрофон;
  - `MODE_IN_COMMUNICATION` (созвон в Телемосте, Telegram и т.п.) — **созвон**: микрофон + звук других приложений через `MediaProjection` (`AudioPlaybackCapture`, включая `USAGE_VOICE_COMMUNICATION` — голоса собеседников), сводятся в моно;
  - `MODE_IN_CALL` — **звонок**: линия звонка (`AudioSource.VOICE_CALL`), если её отдаёт аудио-HAL, иначе микрофон.

  Пока созвон держит другое приложение, Android отдаёт остальным тишину вместо микрофона и не отдаёт голоса собеседников. Обходит это только право `CAPTURE_AUDIO_OUTPUT` (и `CAPTURE_VOICE_COMMUNICATION_OUTPUT`) — его получает лишь Contact Sync, встроенный в прошивку (см. [apps-backup.md](apps-backup.md), «Тихая установка»). Без него запись созвона пишет тишину. Согласие на `MediaProjection` система спрашивает при каждом старте; без окна — если пакету разрешена операция `PROJECT_MEDIA` (`appops set com.example.contactsync PROJECT_MEDIA allow`; на планшете — в `boot.sh`, потому что разрешение сбрасывается при обновлении системного APK).

  Старт — через `RecordActivity` (разрешения, согласие, запуск сервиса): сервис с микрофоном нельзя запустить из фона. `MeetingRecorderService` пишет PCM 48 кГц → AAC 48 кбит/с (`AacWriter`, `MediaCodec` + `MediaMuxer`) частями по лимиту KB `audioMaxMinutes` (берётся из `/api/settings` при входе, по умолчанию 60 минут) в `files/recordings/<id>/part-N.m4a` + `meta.json` (`RecordingStore`).

  **Подсказка при созвоне.** `CallWatcher` слушает смену режима звука (Android 12+). Созвон или звонок длится дольше 3 с, а запись не идёт — уведомление «Идёт созвон — записать?». Запись, начатая по нему, останавливается сама через 5 с после конца разговора.

  **После остановки** — окно «Куда сохранить запись?» (`SaveRecordingActivity`): название, длина, «Прослушать», список проектов KB (предвыбран проект виджета) и три действия:
  - «В „проект“» — каждая часть становится встречей проекта («Созвон 11.10 14:30 · часть 2») и уходит в очередь отправки;
  - «Сохранить без проекта» — проект ещё не заведён; запись остаётся на планшете;
  - «Не сохранять» — с подтверждением, запись удаляется безвозвратно.

  Если запись остановилась сама, приходит уведомление «Запись готова — куда сохранить?» (действия «В проект…» и «Сохранить без проекта»; удалить из уведомления нельзя). Закрыли окно, ничего не выбрав, — запись остаётся неразобранной. Записи без проекта видны списком в «Базе знаний» (нажатие — то же окно), в виджете — их число. Если процесс умер посреди записи, при следующем запуске незакрытая часть удаляется, а остальное становится неразобранной записью.

  Очередь отправки `MeetingUploads` (WorkManager):
  1. создать встречу (id сохраняется рядом с файлом, чтобы при повторе не создать вторую);
  2. `POST /api/uploads/sign` и PUT файла прямо в S3 KB;
  3. `POST /api/meetings/{id}/audio` с моделью расшифровки по умолчанию (`preselectedModelId` из `/api/model-options`).

  Файл удаляется с планшета только после того, как KB его приняла. Если сессия кончилась, запись ждёт входа и после него уходит сама. Виджет показывает, сколько записей ждёт отправки и как идёт расшифровка отправленных за сутки.
- **Второй экран** — веб-интерфейс KB в WebView с той же сессией. WebView создаётся с размером `MATCH_PARENT`: с размером по умолчанию из `AndroidView` (`WRAP_CONTENT`) WebView считает `100vh` нулём, и сайдбар KB, рассчитанный от высоты экрана, схлопывается до заголовка. Сверху выбор проекта, кнопка «Записать» и обновление; ссылки на другие сайты открываются в браузере, загрузка файлов работает через системный выбор файлов.

## VS Code

Третий экран — VS Code в браузере: code-server на VPS (`http://94.103.9.172:8083`, тот же, что открывает отдельное приложение «VS Code» `com.example.vscodeweb`). Адрес задаётся при сборке: `-PcodeServerUrl=http://host:port`. Страница грузится при первом заходе на экран, а не при запуске лаунчера. Вход по паролю code-server хранится в cookie WebView; у главного экрана своё хранилище, поэтому в первый раз пароль вводится заново, даже если в «VS Code» уже входили. Ссылки на другие сайты открываются в браузере, «Upload…» в проводнике работает через системный выбор файлов. Если сервер не отвечает, вместо редактора — «Нет связи с code-server» и кнопка «Повторить». Код — `launcher/CodePage.kt`.

code-server отдаётся по HTTP, поэтому VS Code предупреждает о небезопасном контексте: буфер обмена и веб-представления расширений могут не работать. Исправится, когда code-server будет за HTTPS. Для release-сборки HTTP до VPS разрешён в `network_security_config`.

## Новости

Карточка «Новости» под Мосбиржей (на узком экране — последней). Новости собирает сервер sync и хранит в своей базе, виджет берёт их с сервера (`/api/news`) — подробно в [docs/news.md](news.md). Вкладки — издания с сервера и «Все»; выбранная вкладка запоминается. Нажатие на заголовок открывает статью в браузере.

## Раскрытие виджетов

Погода (полоса прогноза), «Ближайшее», «Мосбиржа» и «Новости» раскрываются на весь экран нажатием на свободное место карточки (у Мосбиржи — и на строку инструмента). Рамка карточки за 0,5 с растягивается до всего экрана, подробности проявляются следом; закрывает «✕» или «Назад» — с той же анимацией обратно.

| Виджет | Подробный экран |
|---|---|
| Погода | сейчас; сутки по часам — температура, ветер, осадки; 8 дней — погода, минимум и максимум с полосой, ветер; смена города |
| Ближайшее | все события на 14 дней по дням, полные названия, место; «+ Событие» |
| Мосбиржа | таблица: цена, изменение, открытие, минимум – максимум, оборот за день, время последней сделки; «Добавить», долгое нажатие — убрать |
| Новости | вкладки изданий, заголовки с анонсом из ленты в две колонки |

Анимируется только отрисовка (обрезка по рамке и прозрачность), подробный экран раскладывается один раз в полном размере: пересчитывать раскладку на каждом кадре планшету дорого. «База знаний» не раскрывается — у неё свой экран (второй). Код — `launcher/WidgetDetails.kt`.

## Плавность

Проверено 11.10.2026 замером кадров (`dumpsys gfxinfo … framestats`) при прокрутке и жестах.

- **Драйвер GPU** — родной: Mali-G72 MP3, драйвер ARM r26p0 (`ro.hardware.egl=mali`, вендорская часть Android 11 под GSI Android 14), отрисовка — Skia на OpenGL ES 3.2. Программной отрисовки нет.
- **Причина рывков — частота GPU.** Под нагрузкой GPU стоит на минимальной частоте 300 МГц из 900 (`/sys/kernel/ged/hal/current_freqency`, индекс 15 из 16). Вероятная причина: регулятор частоты MediaTek (GED, FPSGO) поднимает её по подсказкам о кадрах от фирменной SurfaceFlinger и PowerHAL, а в GSI их нет (не проверено). Поэтому даже системные «Настройки» тратят на отрисовку кадра около 10 мс, а главный экран (полный экран карточек) — около 15 мс на выдачу команд и swap, плюс 3–5 мс UI-потока: медиана кадра 28 мс (≈35 к/с).
- **Что не помогло.** Release-сборка вместо debug (медиана 29 → 28 мс): UI-поток и так тратит 3 мс. Скрытие WebView базы знаний и VS Code вне их экранов — тоже без заметной разницы, но оставлено: невидимой странице незачем рисоваться (`WebView.showWhen`).
- **Решение — настройка ядра** (root, в `/data/local/boot.sh`, после перезагрузки — вместе со скриптом):
  - `echo 4 > /sys/kernel/ged/hal/custom_boost_gpu_freq` — GPU не ниже 698 МГц (ступень 4 из 16; 0 — 900 МГц, 15 — 300 МГц);
  - `echo 20 > /dev/stune/top-app/schedtune.boost` и `echo 1 > /dev/stune/top-app/schedtune.prefer_idle` — ускорение планировщика для активного приложения, как это делает PowerHAL MediaTek в родной прошивке. Без него поток отрисовки сидит на малых ядрах, и выдача команд GPU занимает 8 мс.

  | Вариант | Медиана кадра | 90-й перцентиль | Выдача команд + swap |
  |---|---|---|---|
  | как было (GPU 300 МГц) | 28 мс | 53 мс | 8,5 + 6,5 мс |
  | GPU от 580 МГц | 25 мс | 48 мс | 8,4 + 3,8 мс |
  | GPU от 698 МГц | 21 мс | 42 мс | 8,4 + 3,4 мс |
  | GPU от 580 МГц + планировщик | 17 мс | 40 мс | 6,5 + 3,6 мс |
  | **GPU от 698 МГц + планировщик** (выбрано) | **15 мс** | **32 мс** | 6,4 + 3,1 мс |

  Цена — немного больше нагрев и расход батареи; планшет стоит на зарядке.
- **Сборка.** Release подписывается debug-ключом этой машины и ставится поверх debug без потери данных: `./gradlew assembleRelease`, затем `adb shell cmd package compile -m speed -f com.example.contactsync` (полная AOT-компиляция).

## Поиск Яндекса

Своя строка, готовый виджет Яндекса не используется. При вводе — подсказки из открытого `suggest.yandex.ru` (без ключа). Поиск по Enter, по «Найти» или по подсказке открывает `yandex.ru/search/?text=…` в браузере по умолчанию. Выжимку результатов (Yandex Search API в Yandex Cloud, платно, по ключу) пока не делаем: страница поиска Яндекса на запросы не из браузера отвечает капчей.

## Лампочка VPN

VPN планшета — не Android VpnService, а `openconnect` под root в Alpine Linux (`/data/local/oc`). Он постоянно переподключается к `94.103.9.172:4443`, а наружу ходит через туннель приложения Incy. Системные API такой VPN не видят, поэтому `VpnLamp` проверяет интерфейс `oc0` (поднят и есть IPv4) и TCP-ответ KB, которая доступна только через туннель:
- зелёная — туннель есть и KB отвечает;
- жёлтая — `oc0` есть, KB не отвечает (переподключается);
- красная — `oc0` нет.

**Лампочка в строке состояния** — та же точка поверх всех приложений, слева от значка Wi-Fi: зелёная, жёлтая, красная и серая (выключен из меню) — как на главном экране. Её рисует служба «Панель навигации» (`NavBarService`) окном специальных возможностей: значок уведомления для этого не годится — строка состояния красит его в один цвет. Туннель проверяется раз в 10 секунд (`VpnLamp.probe`). Нажатия проходят сквозь точку, шторка открывается как обычно. Положение — 63 dp от правого края (батарея и Wi-Fi на этом планшете); новые системные значки (Bluetooth, будильник) появляются левее Wi-Fi и могут оказаться под точкой. Без включённой службы лампочки нет.

Нажатие на лампочку открывает меню: состояние, адрес планшета в туннеле и «Выключить VPN» / «Включить VPN». Выключенный пользователем VPN — серая лампочка «VPN выключен», пока переключение идёт — «VPN включается…» / «выключается…».

**Как устроено включение и выключение.** openconnect работает под root, а приложению root не выдаётся. Поэтому приложение пишет желаемое состояние (`on`/`off`) в свой файл `files/vpn-wanted`, а служба под root `tablet/vpnctl.sh` (на планшете — `/data/local/oc/vpnctl.sh`) раз в 2 с читает его и вызывает `occtl.sh start|stop`. Служба раз в 2 с обновляет время изменения `files/vpn-watch` (в цикле только встроенные команды оболочки: внешние `cat`, `date` каждые 2 с держали около 5% ядра); если отметки нет больше 10 с, меню пишет «Управление недоступно: служба vpnctl не запущена». Пока переключение не дошло до туннеля, приложение проверяет его каждые 2 с. Журнал службы — `/data/local/oc/vpnctl.log`. Выбор переживает перезагрузку: если VPN выключен, служба после запуска его остановит.

Установка службы:

```bash
adb push tablet/vpnctl.sh /data/local/tmp/vpnctl.sh
adb shell "su -c 'cp /data/local/tmp/vpnctl.sh /data/local/oc/ && chmod 755 /data/local/oc/vpnctl.sh'"
```

Запускает её `boot.sh` (строка `nohup /data/local/oc/vpnctl.sh > /dev/null 2>&1 &`, см. `tablet/boot.sh`). Запущенный вручную через `adb shell` процесс держит команду adb открытой — её можно прервать Ctrl+C, служба продолжит работать.

## Своя панель навигации

Системные «назад / домой / недавние» рисует Launcher3 в своей панели задач, встроить их в чужой главный экран нельзя. Поэтому:
- системная навигация переключается на жесты (панель задач сворачивается в полоску);
- на главном экране кнопки стоят справа в ряду дока;
- в остальных приложениях служба специальных возможностей `NavBarService` («Панель навигации») рисует тёмную капсулу с теми же кнопками в правом нижнем углу (`performGlobalAction`). Капсула прячется на главном экране, при открытой клавиатуре и при развёрнутой шторке или экране блокировки.

Ограничения: капсула лежит поверх приложений и может закрывать их правый нижний угол; «Недавние» работают только при включённой службе. Служба не читает содержимое экранов — только список окон.

## Автозапуск при загрузке

В прошивке планшета нет места для своих скриптов автозапуска (Magisk, `service.d`), а системный раздел меняем только ради самого Contact Sync (priv-app, см. [apps-backup.md](apps-backup.md)). Поэтому `BootReceiver` после загрузки (`BOOT_COMPLETED`) один раз выполняет через `su` скрипт владельца `/data/local/boot.sh`, если он есть. Журнал пишется в `/data/local/boot.log`.

Скрипт лежит в каталоге, доступном только root, иначе его мог бы подменить любой процесс. Root приложению выдаёт суперпользователь при первом запуске. Нет скрипта или не дали root — загрузка идёт как обычно.

**Ограничение прошивки.** Root приложениям на TrebleDroid выдаёт менеджер phh Superuser (`me.phh.superuser`). Его на планшете нет: готового APK нет, только исходники, а Google Play на планшете нет. Без него `su` из приложения отклоняется, и скрипт при загрузке не выполняется. Из `adb shell` root работает, поэтому после перезагрузки скрипт запускают вручную: `adb shell "su -c 'sh /data/local/boot.sh'"`. Автоматически заработает, если поставить phh Superuser (собрать из исходников) или Magisk.

Звуки интерфейса система загружает один раз при старте. Поэтому после подмены их нужно перечитать (`AudioManager.unloadSoundEffects/loadSoundEffects`). Это делает `BootReceiver` после скрипта, а главный экран — при возврате на него, если в `/proc/mounts` изменилось число подмен в `/media/audio/ui/` (`UiSounds`). Звуки блокировки системная оболочка тоже читает один раз, поэтому скрипт в конце перезапускает её (`pkill -f com.android.systemui`).

Скрипт на планшете — копия [tablet/boot.sh](../tablet/boot.sh): openconnect, службы `vpnctl.sh` и `wifiwatch.sh`, подмена звуков, настройки GPU и планировщика, отрисовка через Vulkan, перезапуск системной оболочки. Прежние версии — `/data/local/boot.sh.bak`, `.bak2`, `.bak3`.

## Wi-Fi

- **Сторож** (`tablet/wifiwatch.sh`, на планшете `/data/local/wifiwatch.sh`, запускается из `boot.sh`). После выключения экрана Wi-Fi иногда остаётся подключённым без связи. Раз в 30 с сторож проверяет, отвечает ли шлюз текущей сети; адрес шлюза берётся из таблицы маршрутов `wlan0`, а не зашит — у разных роутеров он разный. Три неудачи подряд — Wi-Fi перезапускается (не чаще раза в 5 минут); выключенный пользователем Wi-Fi не трогается. Журнал — `/data/local/wifiwatch.log`.
- **Проверка доступа в интернет — через наш сервер.** Android после подключения проверяет интернет запросом к серверам Google, а из нашей сети они отвечают не всегда — тогда сеть помечается «без доступа в интернет». На сервере sync есть `GET /generate_204` (пустой ответ 204, без авторизации), планшет переключается на него настройками:

  ```bash
  adb shell settings put global captive_portal_use_https 0
  adb shell settings put global captive_portal_http_url http://94.103.9.172:8001/generate_204
  adb shell settings put global captive_portal_https_url http://94.103.9.172:8001/generate_204
  adb shell settings put global captive_portal_fallback_url http://94.103.9.172:8001/generate_204
  adb shell settings put global captive_portal_other_fallback_urls http://94.103.9.172:8001/generate_204
  ```

  Включено 11.10.2026: проверка `http://94.103.9.172:8001/generate_204` отвечает 204 примерно за 0,3 с, сеть получает отметку «есть интернет». Настройки сохраняются после перезагрузки. Если сервер недоступен, проверка не пройдёт ни в одной сети и Android покажет «без доступа в интернет» — сама связь при этом работает. Запись `PROBE_DNS 94.103.9.172 … FAIL` в журнале (`dumpsys network_stack`) безвредна: адрес задан IP.

## Оптимизация системы

Сделано 11.10.2026, кроме настроек из «Плавности»:

- **Vulkan** вместо OpenGL для отрисовки интерфейса (`setprop debug.hwui.renderer skiavk` в `boot.sh`; действует на приложения, запущенные после). Медиана кадра главного экрана 18 → 16 мс, отрисовка на GPU (swap) 3,4 → 2,8 мс, артефактов нет. Свойство сбрасывается при перезагрузке.
- **Анимации ×0,5** — `window_animation_scale`, `transition_animation_scale`, `animator_duration_scale` (настройки `global`, сохраняются).
- **Firefox и ChatGPT без фона**: `cmd appops set <пакет> RUN_ANY_IN_BACKGROUND ignore` и `am set-standby-bucket <пакет> restricted`. Telegram — исключение, ему фон нужен для уведомлений. Доступная память после выгрузки 1,34 → 1,54 ГБ.
- **Magisk не ставим** — решение владельца.
- **WebView без Google.** Экраны KB и VS Code открываются в системном WebView (Chromium). В манифесте приложения отключены проверка адресов Safe Browsing (`android.webkit.WebView.EnableSafeBrowsing=false`) и отправка статистики (`android.webkit.WebView.MetricsOptOut=true`) — оба ходят на серверы Google. Сам WebView оставлен: без него не работают экраны KB и VS Code и встроенные страницы других приложений.
- **Обращения к Google, которые остались** (на 11.10.2026): синхронизация времени (`time.android.com`), A-GPS (`supl.google.com`, зашит в системный раздел, только при запросе геолокации), приложения Gemini и NotebookLM. Сервисов Google Play на планшете нет; служба `com.google.android.iwlan` — звонки по Wi-Fi, в Google не ходит.

## Как включить

Поставить APK и выбрать «Главный экран» в «Настройки → Приложения → Приложения по умолчанию → Главный экран». Через adb:

```bash
adb shell cmd package set-home-activity com.example.contactsync/.launcher.LauncherActivity
```

Вернуть стандартный лаунчер — тем же способом выбрать Quickstep или:

```bash
adb shell cmd package set-home-activity com.android.launcher3/.uioverrides.QuickstepLauncher
```

Переустановка APK может сбросить выбор главного экрана — после `adb install` повторить команду выше. Адрес сервера на VPS зашит в APK по умолчанию: `make install-apk`.

Своя панель навигации:
1. «Настройки → System → Gestures → System navigation → Gesture navigation».
2. «Настройки → Accessibility → Панель навигации» — включить.

## Календарь sync

Календарь sync ([docs/calendar.md](calendar.md)) записывает события в календарь Android под своим аккаунтом, поэтому они сами попадают в «Ближайшее». Главный экран при возврате на него просит систему синхронизировать календарь (не чаще раза в 5 минут), а разрешение на календарь запрашивает сразу на чтение и запись.
