# Менеджер паролей

Статус: реализовано (сервер, Android-клиент, сервис автозаполнения).

Пароли от других приложений и сайтов хранятся зашифрованными на сервере. На новом телефоне после входа в аккаунт и разблокировки хранилища автозаполнение подставляет их в одно касание. Сессии сторонних приложений так не переносятся — только логины и пароли (почему — в [apps-backup.md](apps-backup.md)).

## Шифрование

Сервер не может прочитать пароли: всё шифруется и расшифровывается на устройстве.

```
мастер-пароль ──PBKDF2-HMAC-SHA256 (600 000 итераций, соль)──▶ мастер-ключ   (не покидает устройство)
ключ хранилища = случайный AES-256
protectedKey   = AES-GCM(мастер-ключ, ключ хранилища)                       (хранится на сервере)
запись         = AES-GCM(ключ хранилища, JSON записи, AAD = id записи)      (хранится на сервере)
```

- **Мастер-пароль отдельный от пароля аккаунта.** Пароль аккаунта уходит на сервер при входе. Если бы ключ получали из него, сервер мог бы расшифровать хранилище.
- **Смена мастер-пароля** перешифровывает только `protectedKey`, записи не трогаются. На других устройствах новый пароль нужен при следующей разблокировке. Разблокировка по отпечатку продолжает работать: ключ хранилища тот же.
- **Id записи идёт в AAD.** Шифротекст одной записи нельзя незаметно подставить на место другой.
- **Забытый мастер-пароль** не восстанавливается. Хранилище можно только сбросить: на телефоне в настройках или администратором в админке. Пароли при этом теряются.
- **Разблокировка по отпечатку.** Ключ хранилища дополнительно шифруется ключом Android Keystore, доступным только после биометрии (`BIOMETRIC_STRONG`). Добавление нового отпечатка его аннулирует.
- **Автоблокировка** через 5 минут бездействия.
- **Параметры KDF** хранятся на сервере вместе с хранилищем, поэтому их можно усилить позже. Сервер не принимает меньше 600 000 итераций (рекомендация OWASP).

## Запись

```json
{
  "title": "example.com",
  "username": "anna",
  "password": "текущий",
  "uris": ["https://example.com", "androidapp://com.example.app"],
  "notes": "",
  "history": [{ "password": "прежний", "changedAt": 1727430000000 }],
  "createdAt": 1727400000000,
  "modifiedAt": 1727430000000,
  "passwordChangedAt": 1727430000000
}
```

Запись привязана к сайтам (по регистрируемому домену: `accounts.example.com` = `example.com`, но `bank.co.uk` ≠ `other.co.uk`) и к приложениям (по имени пакета).

## Как обновляются пароли

Главное правило: **пароль никогда не теряется**. Любой вытесненный пароль попадает в историю записи (последние 10), откуда его можно скопировать.

### 1. Смена пароля в другом приложении или на сайте

Сервис автозаполнения просит Android сообщить, когда пользователь отправит форму с паролем. Дальше:

| Ситуация | Что происходит |
|---|---|
| Для этого сайта или приложения нет записи с таким логином | предлагается сохранить новую запись |
| Запись с тем же логином есть, пароль другой | предлагается **обновить**; старый пароль уходит в историю |
| Пароль тот же | ничего не делаем |
| Форма смены пароля (поля «старый / новый / повтор», логина нет) | берётся последний пароль формы; если запись для сайта одна — обновляется она |

Окно подтверждения прямо говорит, что произойдёт («Пароль изменился. Обновить? Прежний останется в истории»). Если хранилище заблокировано, в том же окне можно его разблокировать. На Android 8.0–8.1 окна нет: при разблокированном хранилище изменение применяется сразу, при заблокированном пароль не сохраняется.

Пароль из формы не пишется на диск и не передаётся через Intent: до подтверждения он лежит в памяти процесса.

### 2. Одна запись изменена на нескольких устройствах

Оптимистичная блокировка по ревизиям:

1. У хранилища на сервере есть счётчик ревизий. Каждая принятая правка записи получает следующий номер.
2. Устройство отправляет правку вместе с ревизией, от которой оно её делало (`baseRevision`).
3. Если запись за это время никто не менял — правка принимается.
4. Если меняли — сервер отвечает `conflict` и присылает текущую версию. Свести версии может только клиент: сервер не видит содержимого.
5. Клиент расшифровывает обе версии и сводит их (`VaultLogic.merge`):
   - пароль — из версии, где его меняли позже (`passwordChangedAt`), проигравший — в историю;
   - остальные поля — из версии с более поздней правкой (`modifiedAt`);
   - адреса и история объединяются.

   Результат не зависит от того, какое устройство сводит, — оба сходятся к одной версии.
6. Сведённая версия отправляется от новой ревизии.

**Правка побеждает удаление.** Если на одном телефоне запись удалили, а на другом в это же время поменяли, запись остаётся: лишняя запись лучше потерянного пароля.

### 3. Доставка изменений на другие устройства

- Правка сразу пишется локально в очередь исходящих изменений (уже зашифрованной) и отправляется, как только появится сеть.
- Получение — только изменений после последней известной ревизии (`GET /api/vault/items?since=N`), включая удаления (запись-«надгробие» без данных).
- Для отправки и получения ключ не нужен: гоняется только шифротекст. Поэтому фоновая синхронизация (раз в 6 часов и после изменения контактов) работает и при заблокированном хранилище. Только сведение конфликта ждёт разблокировки.
- Локальная копия шифротекстов позволяет автозаполнению работать без сети.

## API

| Метод | Путь | Назначение |
|---|---|---|
| GET | `/api/vault` | параметры ключа (`kdfAlgorithm`, `kdfIterations`, `kdfSalt`, `protectedKey`, `revision`); `404` — хранилища нет |
| POST | `/api/vault` | создать хранилище; `409` — уже есть |
| PUT | `/api/vault/key` | смена мастер-пароля (новые соль и `protectedKey`) |
| DELETE | `/api/vault` | сбросить хранилище |
| GET | `/api/vault/items?since=N` | записи, изменённые после ревизии N |
| POST | `/api/vault/items` | `{changes: [{id, baseRevision, data, deleted}]}` → по каждой правке `ok` (+ `revision`), `conflict` (+ `current`) или `rejected` |

Правки одного хранилища сериализуются блокировкой строки хранилища (`SELECT … FOR UPDATE`) — счётчик ревизий общий.

## Автозаполнение

- Сервис `VaultAutofillService` ищет поля логина и пароля по `autofillHints`, HTML-атрибутам (`type`, `autocomplete`), `inputType`, затем по id и подсказке поля. Если явного поля логина нет, логином считается текстовое поле перед паролем.
- Для браузеров запись ищется по домену страницы, для приложений — по пакету.
- Заблокировано → в подсказке пункт «Разблокировать», по нажатию — окно разблокировки, после неё — подходящие логины.
- Включается пользователем: экран «Пароли» → «Включить автозаполнение» (системная настройка).

## Ограничения

- Chrome передаёт формы сторонним сервисам автозаполнения, только если в его настройках выбран режим «Автозаполнение с помощью другого сервиса». Другие браузеры поддерживают Autofill Framework по-разному.
- Разбор форм эвристический: на нестандартных формах поля могут не распознаться.
- Сопоставление доменов использует упрощённый список составных доменных зон (`co.uk`, `com.au`, `msk.ru` и т. п.), а не полный Public Suffix List.
- Passkeys (Credential Manager provider) не реализованы — следующий шаг.
- Злоумышленник с API-токеном пользователя может сбросить или «перезаписать» хранилище (DoS), но не прочитать его.
